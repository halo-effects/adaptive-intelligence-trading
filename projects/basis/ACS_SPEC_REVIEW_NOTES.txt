ACS Spec Review — Notes for Alex / Claude
==========================================
From: Diamond + GeeGee review session, 2026-03-27

The spec is solid and nearly ready to build. Below are the tweaks and one
addition that came out of our review. Everything else in the original spec
is approved as-is.


1. PHASE-ADAPTIVE WINDOW SCALING (NEW)
---------------------------------------
The 30-day rolling windows assume Phase 3 duration (~3 months). Phase 1
is only ~2 weeks, Phase 2 is ~4-6 weeks. Agents performing perfectly in
a short phase would score poorly because of zero-days padding the window.

FIX: Add one config variable:

    PHASE_LENGTH_DAYS = 14   // change per phase (14, 42, 90, etc.)

All windows and thresholds derive from it:

    scaleFactor = PHASE_LENGTH_DAYS / 90

    // Windows: scale down, round up, minimum 1 day
    effectiveWindow = max(1, ceil(baseWindow * scaleFactor))

    // Thresholds: scale down, round up, minimum 2
    effectiveThreshold = max(2, ceil(baseThreshold * scaleFactor))

Applied to each component:

    Component 1 (ERC-8004):         No window, no threshold. Unchanged.
    Component 2 (Tx Consistency):   Window scales (30d base). CV formula adapts naturally.
    Component 3 (Timing Entropy):   Window scales (30d base). Entropy formula adapts naturally.
    Component 4 (Session Chains):   Window scales (30d base). Threshold scales (10 bursts base).
    Component 5 (Feature Coverage): Window scales (7d base). Threshold scales (15 categories base).
    Component 6 (Vol-Weighted):     Window scales (30d base). Thresholds scale (10 contracts base, 30 days base).
    Component 7 (Longevity):        No window (all-time). Unchanged.

Example values per phase:

    Phase 1 (14d):  scaleFactor = 0.156
      Tx Consistency window:    max(1, ceil(30 * 0.156)) = 5d
      Timing Entropy window:    5d
      Session Chains window:    5d,  threshold: max(2, ceil(10 * 0.156)) = 2 bursts
      Feature Coverage window:  max(1, ceil(7 * 0.156)) = 2d,  threshold: max(2, ceil(15 * 0.156)) = 3 categories
      Vol-Weighted window:      5d,  thresholds: max(2, ceil(10 * 0.156)) = 2 contracts / 5 days

    Phase 2 (42d):  scaleFactor = 0.467
      Tx Consistency window:    max(1, ceil(30 * 0.467)) = 14d
      Timing Entropy window:    14d
      Session Chains window:    14d, threshold: max(2, ceil(10 * 0.467)) = 5 bursts
      Feature Coverage window:  max(1, ceil(7 * 0.467)) = 4d,  threshold: max(2, ceil(15 * 0.467)) = 7 categories
      Vol-Weighted window:      14d, thresholds: max(2, ceil(10 * 0.467)) = 5 contracts / 14 days

    Phase 3 (90d):  scaleFactor = 1.0
      Everything at base values (30d, 7d, 10 bursts, 15 categories, etc.)

The beauty: Alex sets one number (PHASE_LENGTH_DAYS) and everything
scales. If Phase 1 ends up being 20 days instead of 14, just change
the number.


2. BURST DETECTION ITERATION CLARITY
--------------------------------------
In Component 4, the spec says "For each tx, look ahead: collect all txs
within 60s." Clarify the iteration:

    - If the window qualifies as a burst (3+ txs, 2+ contracts):
      increment burst count, advance pointer to END of burst window
    - If it does NOT qualify: advance pointer by 1 tx

This prevents double-counting transactions that appear in overlapping
60-second windows.


3. FEATURE COVERAGE WINDOW MISMATCH
-------------------------------------
Component 5 uses a 7-day base window (from diversityCP), while all other
rolling components use 30-day base windows. This is fine — it's
intentional because it piggybacks on the existing diversityCP computation
in the points cycle. Just noting it so there's no confusion about why
it's different. The phase scaling still applies (7d * scaleFactor).


4. REEF GATING PLACEHOLDER
----------------------------
ACS will determine access to the Agents section of The Reef (the
community forum). The spec should include a placeholder:

    REEF_AGENT_THRESHOLD = TBD   // suggested range: 30-50

    Wallet access to Reef "Agents" section:
      if (wallet.acsScore >= REEF_AGENT_THRESHOLD) → agents section unlocked
      else → everyone section only

Exact threshold to be determined after observing Phase 1 score
distributions.


5. VOLUME-WEIGHTED BREADTH — NOTE ON NEW AGENTS
-------------------------------------------------
The multiplicative formula (contracts/threshold) * (days/window) can
produce low scores for new agents. This is intentional — it filters
drive-by wallets. The score self-corrects as agents accumulate active
days. With phase scaling, this is even less of a concern (Phase 1's
smaller window means fewer days needed).
