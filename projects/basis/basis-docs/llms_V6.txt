## Faucet (Daily USDB Drip)
- Endpoint: POST /api/v1/faucet/claim (SIWE session required)
- Max: 500 USDB/day (signal-based: base 150 + twitter 100 + active 100 + hatchling 100 + tidal 150)
- Identity gate: ERC-8004 agent registration OR username + linked social account (Discord/GitHub/Google/X)
- 24-hour cooldown. Server-side drip — no on-chain tx from your wallet.
- SDK: client.claimFaucet(referrer?) — referrer sets permanent on-chain referral link on first claim
- Check status: client.api.getFaucetStatus() → { canClaim, dailyAmount, signals, nextClaimAt }

## API Key Behavior
- Created automatically on first BasisClient.create() with privateKey
- Full key shown ONCE at creation time — save it immediately
- Subsequent listApiKeys() returns masked hints only (bsk_****XXXX)
- Pass saved key via apiKey / api_key option on subsequent runs to avoid re-creation
- Rate limits: 60 req/min (API key), 30 req/min (session), 20 req/min (sync endpoint)

## Airdrop
- 11% of total BASIS token supply allocated to participants across 3 phases
- Phase 1: 1% | Phase 2: 2% | Phase 3: 8%
- Every on-chain action earns points toward your allocation
- Tokens earned per phase are banked permanently — they are yours
- Phase 1 participants earn from the smallest, most exclusive pool
- Floor FDV: $150M guaranteed at TGE

## ⚠️ Transfer Warning — READ BEFORE TRANSACTING
- Any wallet-to-wallet transfer of USDB or ANY platform token (STASIS, factory tokens, Predict+ tokens — everything) automatically flags BOTH THE SENDER AND RECEIVER for review and suspends their airdrop points.
- Subject to an appeals/dispute process, wallets found to be funding other wallets, splitting activity across multiple addresses, or engaging in sybil patterns will be PERMANENTLY DISQUALIFIED from all airdrop rewards.
- Accidental transfers (code bugs, wrong address) can be disputed and reinstated through the appeals process.
- All legitimate activity (trading, lending, staking, betting) goes through the DEX and protocol contracts — there is no valid reason for direct wallet-to-wallet transfers during the testing phase.
- If you are building an agent: DO NOT programmatically transfer tokens between wallets. Use only SDK trading, lending, and staking methods which route through the protocol contracts.
- GRIEFING PROTECTION: If your wallet receives unsolicited tokens from an unknown sender:
  1. Do NOT use the tokens — don't trade, stake, or interact with them in any way.
  2. Report immediately through the platform's support channel with your wallet address and the tx hash.
  3. BURN the griefed tokens by sending them to 0x000000000000000000000000000000000000dEaD — this creates on-chain proof you rejected the tokens and prevents accidental use.
  4. Continue using the platform normally — the appeals process covers griefing victims. Points are suspended until review clears.
  For agents: this is critical. An automated trading bot cannot selectively avoid tokens in its wallet. Burn to dead address immediately to eliminate the risk.
