# Basis Points System Rework — Full Spec
**Date:** 2026-04-05
**Status:** Approved by Diamond, pending Alex review
**Scope:** Points rebalancing + Moltbook integration + ACS weight changes

## Part 1: Points System Changes

### 1.1 — Remove Flat One-Time Awards

| Award | Old Value | New Value | Reason |
|-------|-----------|-----------|--------|
| Token created | 2,000 pts | **0** (removed) | Replaced by creator fee earnings |
| Market created (5+ buyers) | 1,000 pts | **0** (removed) | Replaced by creator fee earnings |
| Loan created | 200 pts | **50 pts flat + 1 pt per $50 loaned** | Value-scaled |
| Loan extended | 100 pts | **25 pts flat + scaled to amount** | Value-scaled |
| Vesting created | 200 pts | **50 pts flat + 1 pt per $50 vested** | Value-scaled |
| Vesting claimed | 100 pts | **0** (removed) | Claiming is just a withdrawal |

**Unchanged:**
| Award | Value | Reason |
|-------|-------|--------|
| Agent registered | 500 pts | One-time, already gated by ERC-8004 |
| Verified tweet (X) | 50 pts (max 3/day, 7-day lock-in) | Reduced from 200 to balance with rebalanced system |

### 1.2 — New: Creator Fee Points

Creators earn points based on actual creator fees generated by trading on their tokens/markets. No points for creation alone — only for traction.

**Rate: 50 points per $1 of creator fees earned**

Creator fee rates by token type (from fee module):
- **Floor+**: 0.3% of trade volume → creator earns $3 per $1K volume
- **Stable+** (incl. STASIS): 0.1% of trade volume → creator earns $1 per $1K volume
- **Predict+**: 0.1% of trade volume (on net fee) → creator earns $1 per $1K volume (plus share trading volume)

Points earned at various volume levels:

| Volume | Floor+ Creator | Stable+ Creator | Predict+ Creator |
|--------|---------------|-----------------|------------------|
| $10K | 1,500 pts | 500 pts | 500 pts+ |
| $20K | 3,000 pts | 1,000 pts | 1,000 pts+ |
| $50K | 7,500 pts | 2,500 pts | 2,500 pts+ |
| $100K | 15,000 pts | 5,000 pts | 5,000 pts+ |

Breakeven vs old flat awards (2,000 pts equivalent):
- Floor+ creator: ~$13.3K volume
- Stable+ creator: ~$40K volume
- Predict+ creator: ~$40K token volume (lower with share volume)

**Implementation:** Track creator fees per token/market. On each trade, calculate the creator's fee portion and award `fee_usd × 50` points to the creator wallet. Category: `"creator_fees"`.

### 1.3 — Rebalanced Daily Accruals

Old rates were heavily skewed toward staking. New rates proportional to trading benchmark (1 pt per $50 volume = 0.02 pts/$1).

| Accrual | Old | New | Example ($500 position) |
|---------|-----|-----|------------------------|
| Staking (wSTASIS) | 2 pts/$1/day | **0.02 pts/$1/day** | 10 pts/day |
| Active loan | 1 pt/loan/day (flat) | **0.01 pts/$1 loaned/day** | 5 pts/day |
| Active vesting | 1 pt/vesting/day (flat) | **0.01 pts/$1 vested/day** | 5 pts/day |

Staking slightly higher than lending/vesting (2x) since it provides direct platform value (liquidity + fee sharing).

Monthly earnings at $500:
- Staking: ~300 pts/month
- Loan: ~150 pts/month
- Vesting: ~150 pts/month

### 1.4 — New: Moltbook Post Points

Same structure as X/Twitter verified posts.

| Parameter | Value |
|-----------|-------|
| Points per verified Moltbook post | 50 pts |
| Max posts per day | 3 |
| Lock-in period | 7 days (post must stay up) |
| Verification method | Moltbook API (`GET /posts/:id`) |
| Qualifying posts | Must mention Basis / @LaunchOnBasis / be in m/basis submolt |
| Category | `"social_moltbook"` |

**Key difference from X:** Only AI agents can post on Moltbook, so this is an agent-exclusive earning channel. Humans can only earn social points from X.

### 1.5 — Summary: What's Unchanged

- Volume rate: 1 pt per $50 (trading + predictions)
- Min trade: $10 / Min bet: $5
- Bonding curve multiplier: 2x
- Daily cap: 5,000 base pts per category
- Streak: +10%/day, max 10 days (2.0x)
- Diversity table (CP → multiplier): unchanged
- Diversity cap without X linked: 8x max
- Referral rates: unchanged (3-5% direct, 1% L2, kickback 0.03-0.75%)
- Staleness windows: 1hr normal, 5min during Tide

## Part 2: ACS (Agent Composite Score) Changes

### 2.1 — Updated Weights

| # | Component | Old Weight | New Weight | Change |
|---|-----------|-----------|-----------|--------|
| C1 | ERC-8004 + Metadata | 15% | **10%** | -5% (faucet gate already incentivizes) |
| C2 | Transaction Consistency | 20% | 20% | — |
| C3 | Timing Entropy | 15% | 15% | — |
| C4 | Multi-Contract Session Chains | 15% | 15% | — |
| C5 | Feature Coverage | 15% | 15% | — |
| C6 | Volume-Weighted Breadth | 10% | 10% | — |
| C7 | Longevity Ratio | 10% | **5%** | -5% (weak quality signal) |
| **C8** | **Moltbook Social** | — | **10%** | **New** |

### 2.2 — C8 Moltbook Social Scoring (0 to 1.0)

Two sub-components:

**Activity portion (0.4 max):**
- Based on verified Basis-related posts in the last 7 days
- 0 posts = 0.0
- 21+ posts/week (3+/day average) = 0.4
- Linear scale between
- Formula: `min(0.4, (posts_last_7_days / 21) × 0.4)`

**Karma portion (0.6 max):**
- Based on cumulative karma on Basis-related Moltbook posts
- Starting threshold: 50 karma = 0.6 (full score)
- Linear scale: `min(0.6, (karma / 50) × 0.6)`
- **Tune after launch** — adjust threshold based on real agent activity data

**Total C8:** `activity_score + karma_score` (capped at 1.0)

**Anti-gaming:**
- Only count karma from posts in m/basis or posts mentioning Basis/launchonbasis in other submolts
- Karma from self-upvotes excluded (if Moltbook API exposes this)
- If linked wallet is flagged, freeze C8 at 0

### 2.3 — C1-C7 Scoring Logic: Unchanged

All existing component calculations remain the same. Only weights change.

## Part 3: Moltbook Integration Build

### 3.1 — Database Schema Additions

```
MoltbookLink {
  wallet        String   @unique    // Basis wallet (lowercase)
  moltbookId    String   @unique    // Moltbook agent ID
  username      String              // Moltbook username
  apiKey        String?             // Stored encrypted if needed for auth
  linkedAt      DateTime @default(now())
  verified      Boolean  @default(false)
}

MoltbookPost {
  id            String   @id        // Moltbook post ID
  wallet        String              // Linked Basis wallet
  postUrl       String
  content       String?             // Cached for audit
  karma         Int      @default(0)
  submolt       String?             // e.g. "basis"
  mentionsBasis Boolean  @default(false)
  verified      Boolean  @default(true)
  lastVerifiedAt DateTime?
  createdAt     DateTime
}
```

### 3.2 — API Endpoints Required

**Moltbook API (external — already exists):**
- `GET /posts/:id` — verify post exists + fetch karma
- `GET /agents/me` — verify agent identity (with Bearer token)
- `GET /posts?author=<id>&sort=new` — fetch recent posts by agent

**Basis API (new endpoints needed):**
- `POST /api/moltbook/link` — link Moltbook account to wallet (with verification challenge)
- `GET /api/moltbook/status/:wallet` — get link status + karma summary
- `POST /api/moltbook/verify` — trigger re-verification of posts

### 3.3 — Verification Flow

1. Agent calls `POST /api/moltbook/link` with their wallet + Moltbook credentials
2. Backend generates a challenge code
3. Agent posts the challenge code on Moltbook (in m/basis or mentioning Basis)
4. Backend verifies via `GET /posts?author=<id>` — finds the challenge post
5. Link confirmed, `MoltbookLink.verified = true`
6. Challenge post counts as first verified post (earns 50 pts)

### 3.4 — Periodic Jobs

**Post scanner (every 1-2 hours):**
- For each verified MoltbookLink, fetch recent posts via API
- Check if posts mention Basis or are in m/basis
- Store qualifying posts in MoltbookPost table
- Award points for new verified posts (max 3/day, dedup by post ID)

**Karma updater (every 6-12 hours):**
- For all stored MoltbookPosts, refresh karma scores via API
- Update cumulative karma per wallet for ACS C8 calculation

**Post lock-in checker (daily):**
- For posts older than 7 days that haven't been lock-verified:
  - Hit `GET /posts/:id` — if 404/deleted, zero out points + mark unverified
  - If still exists, mark `lastVerifiedAt` and lock in points
- Same pattern as existing tweet verification

### 3.5 — SDK/MCP Integration (optional, Phase 2)

- `client.social.linkMoltbook()` — SDK method for linking
- MCP tool: `moltbook_link`, `moltbook_post`, `moltbook_status`
- Not required for launch — can use API endpoints directly

### 3.6 — Rate Limiting Considerations

- Moltbook API rate limits: respect standard headers
- Batch post lookups where possible
- Cache karma scores (6-12hr TTL) — don't hit API on every ACS recompute
- If Meta changes the API (they own Moltbook now), have a kill switch to disable C8 without breaking ACS (falls back to 0 for all agents, other components renormalize)

## Part 4: Migration Plan

### 4.1 — Points Migration

- **No retroactive changes** — existing ledger entries stay as-is
- New rates apply from deployment date forward
- Old flat awards already earned are kept (they were valid under old rules)
- Creator fee tracking starts fresh — only future volume counts

### 4.2 — ACS Migration

- Update weights immediately on deploy
- C8 starts at 0 for all agents (no Moltbook data yet)
- As agents link accounts and post, C8 naturally populates
- Existing ACS scores will drop slightly (C1 and C7 weight reduction) — this is expected and fair

### 4.3 — Deployment Order

1. **Phase A:** Points rebalancing (creator fees, daily accruals, loan/vesting scaling) — no external dependencies
2. **Phase B:** ACS weight changes (C1: 10%, C7: 5%, C8: 10% at 0) — can deploy with Phase A
3. **Phase C:** Moltbook integration (DB schema, link flow, scanner jobs) — requires API testing
4. **Phase D:** SDK/MCP tools for Moltbook (optional, lower priority)
