## Trend Multiplier Fix + Aster Revert Recovery (5:10 AM - 6:30 AM)

### Problem
Dashboard Trend Mult columns showing `--` for all coins. Trade Score = Base Score (no trend weighting).

### Root Cause
1. **32-day gap in score_history.json** (March 17 → April 18). Scanner wasn't running daily during that period.
2. `compute_trend_scores()` filters snapshots into 7d/14d/30d windows relative to latest. With all prior snapshots >32 days old, every window had only 1 point (the latest, days_ago=0). Needs ≥2 points → all windows returned None → empty `trend_scores` → `if trends:` was false → `trend_scores` never added to output JSON.
3. Dashboard JS checks `scannerData.trend_scores[coinKey]` → undefined → falls through to `--` default.

### Fix 1: Gap Resilience (code)
- Added fallback in `compute_trend_scores()`: when no standard window has ≥2 points but ≥2 snapshots exist overall, compare the two most recent snapshots regardless of gap.
- Slope assigned to the window best matching the actual gap (≤10d→7d, ≤21d→14d, else→30d).
- Logged as info for debugging.

### Fix 2: Aster Collector Revert
- Discovered that `git merge` from remote `main` (commit `17c2e37d8`) had silently reverted `collect_scanner_candles.py` back to Hyperliquid. The Aster switch from last night was lost.
- Restored from commit `0d14afd81` via `git checkout`.
- Updated `run_candle_collector.ps1` comment too.

### Fix 3: Score History Rebuild
- Ran scanner with `--backfill-history 3` → seeded April 15/16/17 synthetic snapshots.
- 24 total snapshots now. Trend multipliers active for 45/50 coins.
- 5 new coins (added in last night's Aster sync) will get trends after their second snapshot.
