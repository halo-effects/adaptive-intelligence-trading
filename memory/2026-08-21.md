## V14PM — Undetected TP Fill Bug Fixes Deployed

Implemented 4 fixes for the silent TP fill bug that caused deal #118 (ASTER) -$47.03 loss.

### Fixes
1. **Fix 1 — `_safe_cancel_tp()`**: Wraps `cancel_tp_order` to detect silent fills. When cancel fails, checks `check_order_status()`. If filled → processes via `_handle_tp_fill()`. Wired into 4 cancel sites (place_tp, SELL path, force-close, phase-change). Added empty-result guard (Bug 1.1 from audit) to prevent clearing tp_order_id on API failure.
2. **Fix 2 — Cross-validate invested on TP fill**: `_handle_tp_fill` now does fresh `fetch_open_positions()` (not cached). If divergence >10% → WARNING + Telegram alert. Always corrects to exchange-truth.
3. **Fix 3 — Daily invested audit**: Added to `_daily_health_digest`. Compares all open_deals.invested vs exchange. Log-only (no mutations). Warns >10%, notes >5%.
4. **Fix 4 — Prevent deal accumulation on BUY**: Before `on_buy()`, checks exchange qty vs open_deals qty. If <50% match AND cached positions confirm → clear tp_order_id (Bug 4.1 fix), force-close stale deal. Cross-checks cached positions to prevent false-trigger on API failure (Bug 4.2 fix).
