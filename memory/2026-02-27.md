## Session 9 (Late Morning — Fixing Wrapper vs Standalone Equity Gap)

### Problem: $1,459 Equity Gap Between Standalone and Wrapper Backtests
- Standalone: $27,005 (4 coins), Wrapper: $28,464 — should be identical since both use v8 engine
- XRP alone accounted for $1,002 of the gap

### Debugging Journey (Systematic Elimination)
1. **Prices identical** — tick-by-tick trace showed 0.0000 difference every day. NOT the cause.
2. **Phases identical** — same transitions, same dates, same reasons across all coins.
3. **Trade counts different** — wrapper had 5 extra trades (30 vs 25 for XRP). Extra DCA + tier adds.
4. **Config identical** — dumped all 36 config attributes, all matched perfectly.
5. **Same pack, same config, same run() = identical** — two standalone runs always match.
6. **V13SignalPack coin name was the culprit** — wrapper passed `'XRP'` (stripped), standalone passed `'XRP/USDC'`.

### Root Cause: `load_cfgi()` Bug in `v13_signals.py`
- `load_cfgi()` used the full coin symbol for DB query: `LIKE 'XRP/USDC%'`
- cfgi_daily table stores symbols as `XRP` or `XRP/USDT` — no `XRP/USDC` entry
- So standalone (passing `XRP/USDC`) got **no CFGI data** → NaN on tier gates → no T2/T3 adds
- Wrapper (passing `XRP` via `symbol.split('/')[0]`) found CFGI data → T2/T3 tier adds worked
- `load_daily()` already extracted base coin correctly — `load_cfgi()` didn't

### The Fix (One Line)
- Changed `load_cfgi()` to extract base coin: `base = coin.split('/')[0].upper()`
- Same pattern `load_daily()` already used

### Impact
- Missing CFGI data meant standalone skipped T2/T3 markup adds (CFGI>40 gate failed with NaN)
- XRP: standalone had only T1 buys, wrapper had T1+T2+T3. Extra capital compounded through +374% rally.
- **All prior standalone backtest results were WRONG** — missing CFGI gating for coins passed as `COIN/USDC`

### Verification: 100% Match Achieved
- All 4 coins: $0.0 delta between standalone and wrapper
- ETH $4,167, SOL $3,610, LINK $6,547, XRP $14,114 — all match exactly
- **Total portfolio with fix: $28,438** (was $27,005 without CFGI)

### Also Done: `backfill_direct()` Method
- Added to wrapper (`v13_lifecycle_engine_v2.py`)
- Paper bot backfill now calls v8 engine's `run()` directly instead of tick-by-tick wrapper
- Guarantees backfill matches standalone exactly — no reimplementation drift
- Updated `run_v13_paper.py` to use `backfill_direct()`

### Key Lessons
- **Coin name format inconsistency is a silent killer**: `XRP` vs `XRP/USDC` vs `XRP/USDT` — different parts of the system use different formats. Always normalize to base coin for DB lookups.
- **Missing data ≠ error**: `_cfgi()` returning NaN wasn't an error — it silently disabled CFGI-gated features (tier adds). No warning, no exception. The engine just didn't add tiers.
- **Reimplemented loops always diverge**: The wrapper's tick-by-tick reimplementation of run() had subtle differences. Using run() directly eliminates this class of bugs entirely.
- **Test what you ship**: The standalone backtest used `COIN/USDC` format, but the paper bot used `COIN` format via the wrapper. Different code paths, different results, nobody noticed.
