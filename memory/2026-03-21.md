## V14PM Live Bot � Exchange-as-Truth Refactor (afternoon)

### Problem
Engine state carried stale data from original bot launch (68.17 GRASS/ invested) while
exchange had 635.4 GRASS/ invested. Dashboard showed equity ~ with -70% drawdown.
Actual equity was ~.

### Root Cause
Paper-bot architecture: engine tracked positions via candle simulation, creating two sources
of truth that diverged. LIVE GUARD, rollbacks, and reconciliation were patches that couldn't
keep up. The old single-coin live bot had the SAME fundamental flaw but hid it with a
status-write override. The PM bot exposed the underlying rot.

### Fix Implemented
**Exchange-as-truth architecture** � complete rewrite of position tracking:
- `_sync_positions_from_exchange()` � runs every 65s, overwrites engine position state from API
- `_write_status()` � completely rewritten, ALL data from exchange (not engine)
- Removed: `_reconcile_with_exchange()`, `_periodic_reconcile()`, `_snapshot_engine()`, `_rollback_engine()`
- Removed: LIVE GUARD, pre-tick snapshots, engine rollbacks
- Added: `CoinState.layer_count` for DCA layer tracking (exchange doesn't know about layers)
- Net: ~280 lines removed from bot code

### Result
- equity: .33 (was .17)
- invested: .20 (was .03)
- pnl: +0.39% (was -70.52%)
- All status.json fields present and correct
- Dashboard synced to GitHub Pages

### Docs Updated
- V14PM_VS_V14_LIVE_AUDIT.md � �21 added, summary table updated
- V14PM_SYSTEM_ARCHITECTURE.md � v1.5: �6.8 rewritten, �7.1 updated, �16.4 Phase 3 marked partial

### Key Insight
Both the old V14 Live bot and the PM Live bot had the same two-source-of-truth problem.
The old bot hid it with a status-write exchange override. The PM bot exposed it because
that override wasn't fully ported. The real fix was making the exchange authoritative for
ALL position data, not just the display layer.
