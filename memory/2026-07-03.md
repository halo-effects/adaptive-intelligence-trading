### Context
External audit performed by Claude (Fable) on the full V14PM production system. Scope: all live code, 119 closed trades, scanner, capital manager, architecture docs. ### Executive Summary
**System health: GOOD, with three integrity gaps.** Operational hardening (hard rules, exchange-as-truth, atomic writes, orphan-TP, layer recon) all validated in code. Post-orphan-TP era (after 5/17): 18 deals, +$29.14, 94% WR, worst loss -$0.20. The three -$103.83 catastrophic losses were ALL manual force-closes during upgrades — the strategy itself has never produced a large loss. Core thesis validated.

### 🔴 CRITICAL Findings

**C1 — Three different grids in production.** `engine.live_mode` is write-only (set in 4 places, never read). The 30%-of-remaining-capital paper cap is active in live, producing a *decreasing* grid (30/21/15/10% of allocation) instead of the documented Martingale (40/60/90/135%). Scanner simulates a third grid. Top-up sizes for the documented grid nobody uses. Capital sits partially deployed.

**C2 — `_prune_stale_coin_after_tp()` called but never defined.** The non-TP SELL path raises AttributeError every time → main-loop handler catches it, skips remaining coins that cycle. Affects the candle-based TP fallback (safety net when exchange TPs fail).

### 🟠 HIGH Findings

**H1 — Liquidity filter never executed.** Two attribute errors (`self.client.exchange` should be `self.client._exchange`, `self._aster_symbol` should be `self.client._aster_symbol`), both swallowed by fail-open handlers. $50K minimum volume and 100× allocation multiplier have never gated anything. Not harmful at $423 on majors, dangerous at scale.

**H2 — 1000-prefix double-descale in `create_market_buy` ticker fallback.** When buy order returns no fill price, ticker fallback already divides by 1000 for PEPE/BONK/FLOKI, then code divides again. Poisons avg entry, invested, and TP. Rare path, sell side handles it correctly.

**H3 — Short positions from exchange would sync as longs.** `_sync_positions_from_exchange()` ignores `side` field. Dormant today (long-only), but a landmine for Hyperliquid migration.

**H4 — Overflow entry (`OVERFLOW_ENTRY_ENABLED`) is unreachable.** 7,680 enumerated scenarios: zero admissions. The zombie mechanism (same 6/19 release) cannibalized every case overflow could serve. Deposits strand when all grids are maxed and still top-ranked. Spec written: `overflow-entry-v2-soft-ceiling.md`.
