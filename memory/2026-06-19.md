## Paper Bot PnL Inflation Fix

### Problem
Brett noticed paper dashboard showing 54.48% ROI on HYPE L1 trade (should be ~3% TP). Investigation found 23 trades with >10% return, all correlated with engines created mid-run by rebalance/rotation.

### Root Cause
When `_check_and_rebalance()` or `_rotate_after_tp()` creates a new engine, `_last_candle_ts = 0`. The bot fetches 200 candles from Hyperliquid and processes ALL as live trades. Engine buys at historical price (weeks old), TP triggers at current price = inflated PnL.

### Key Finding: Not a New Bug in the TP Calculation
The March trades all showed exactly 1.48% because the bot ran continuously and coins stayed in approved list. The inflated trades started May 23 when HYPE re-entered after a 77-day gap (regime changes caused coins to drop/re-enter approved list during May audit work).

### Fix
Set `_last_candle_ts = int(time.time() * 1000)` on every new engine creation. Applied to both runners at all engine creation sites (2 each). Live runner already had warmup guard as defense-in-depth.

### Trailing TP Simulation Specced
Paper bot uses fixed `price >= long_tp` (candle close). Live bot uses Aster-native `TRAILING_STOP_MARKET` (3% activation, 0.2% callback). Spec at `projects/ait/specs/paper-trailing-tp-simulation.md` — requires backtest comparison before implementation because OHLC intra-candle ordering is unknown.
