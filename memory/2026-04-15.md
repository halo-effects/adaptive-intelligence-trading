# 2026-04-15 — Trailing Stop Restore & Code Protection

## Incident: Accidental Code Revert (Apr 14)
- Trailing stop TP feature was added Apr 13 (commit 1554a0500)
- An accidental revert on Apr 14 (commit 725703fe8) stripped:
  - `v14_dca_engine.py`: trailing stop state, high/low params, live_mode flag
  - `v14_lifecycle_engine.py`: high/low passthrough, live TP catch-up
  - `run_v14_portfolio_live_aster.py`: **entire file deleted** (3,120 lines)
  - `v14_capital_manager.py`: EQUITY_TIER_SPLITS, hysteresis, ledger functions
  - `cfgi_client.py`, `run_v14_live_aster.py`: regressed
  - 11+ ait-product docs deleted
  - Multiple utility scripts deleted
- PM Live bot started throwing `NameError: name 'low' is not defined` on every tick at 10 PM Apr 14
- Bot was still running but not trading — all engine ticks caught by exception handler

## Fix Applied
1. Restored all code files from commit 1554a0500 (git checkout)
2. **Bug fix**: `_long_dca_tick` was missing `low` parameter in its signature
   - Trailing stop callback needs `low` to detect when price drops from peak
   - Added `low=None` to signature, lifecycle engine now passes both `high` and `low` to both tick functions
3. PM Live bot restarted — PID 12156, 7 coins restored, TP orders verified on exchange
4. All ait-product docs restored (30+ files)

## Root Cause
The "auto-backup" and "Data sync" git commits were overwriting the trailing stop version
with an older state. The auto-backup mechanism doesn't distinguish between code changes
and data changes — it does `git add` on the whole workspace.

## Safeguard Discussion
Brett asked about protecting code from accidental rollback. Options discussed:
- Git branch protection (keep code changes on feature branches)
- Separate data sync from code commits
- Pre-commit hooks to prevent regressions in critical files
