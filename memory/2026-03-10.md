## State Persistence — Root Cause Fix
- Implemented `_save_state()` / `_load_state()` in PM runner
- Saves `engine_state.json` every 60s: engine snapshots, router state, open deals, last candle timestamps
- On restart, engines restore from state file — no candle replay, no phantom trades
- Tested 3 consecutive kill-restart cycles: 22 trades before/after every time, zero phantoms
- Bare engine fallback added to `restore_state()` — if signal pack fails, engine still restores
- Scheduled task `V14PMPaperBot` updated: removed `--fresh` (no longer needed for normal restarts)
- `--fresh` still available for genuinely starting from scratch (new account, new coins)

## Missing Daily Candle Data — Root Cause Found
- **19 coins** had 1h candles but ZERO daily candles in `candles_daily` table
- Missing: COMP, DYDX, EIGEN, ENA, ENS, HBAR, KAS, LDO, MKR, ONDO, OP, PENDLE, PYTH, RENDER, SNX, STX, TIA, W, ZRO
- Root cause: `collect_scanner_candles.py` writes to `candles` (1h), but V13SignalPack reads from `candles_daily`
- **No resampling step existed** — 1h candles were never aggregated into daily
- Created `resample_daily.py`: resamples all 1h symbols → daily candles
- Wired into hourly pipeline (`run_candle_collector.ps1`) as Step 1.5
- First run inserted 24,995 daily candles for 24 symbols
- After resample: all 10 PM engines load signal packs successfully (zero bare engines)

## Fresh Install Path
- `--fresh` IS still needed for a brand new account (no `engine_state.json` exists, no prior trades)

- Subsequent restarts: state persistence handles everything, `--fresh` not needed
