## GitHub Pages Builds Failing — Root Cause & Fix

**Problem:** All GitHub Pages builds for `halo-effects/adaptive-intelligence-trading` were failing (5+ consecutive failures visible in Actions tab). Website content updates (2A — index.html, pricing.html with V14 numbers) were not deploying.

**Root cause:** Broken submodule reference. `repos/intelligent-accumulation-trading` was tracked as a git submodule (mode 160000) but `.gitmodules` file didn't exist. GitHub Pages build couldn't resolve it → instant failure every deploy.

**Fix:** `git rm --cached repos/intelligent-accumulation-trading` in the sync temp repo, committed and pushed. Build #4100+ should succeed.

**Lesson:** Broken submodules silently kill GitHub Pages builds. The CRLF warning in sync script stderr was a red herring — the real issue was the orphaned submodule entry. Always check `git submodule status` if Pages builds fail mysteriously.

**Note:** The fix was applied in the temp sync repo (`$env:TEMP\ait-dashboard-sync`) which is what actually pushes to GitHub. The workspace repo also had the fix committed locally but can't push (401 issue persists).
