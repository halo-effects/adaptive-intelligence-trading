## GitHub Pages Builds Failing — Root Cause & Fix

**Problem:** All GitHub Pages builds for `halo-effects/adaptive-intelligence-trading` were failing (5+ consecutive failures visible in Actions tab). Website content updates (2A — index.html, pricing.html with V14 numbers) were not deploying.

**Root cause:** Broken submodule reference. `repos/intelligent-accumulation-trading` was tracked as a git submodule (mode 160000) but `.gitmodules` file didn't exist. GitHub Pages build couldn't resolve it → instant failure every deploy.

**Fix:** `git rm --cached repos/intelligent-accumulation-trading` in the sync temp repo, committed and pushed. Build #4100+ should succeed.

**Lesson:** Broken submodules silently kill GitHub Pages builds. The CRLF warning in sync script stderr was a red herring — the real issue was the orphaned submodule entry. Always check `git submodule status` if Pages builds fail mysteriously.

**Note:** The fix was applied in the temp sync repo (`$env:TEMP\ait-dashboard-sync`) which is what actually pushes to GitHub. The workspace repo also had the fix committed locally but can't push (401 issue persists).

## V14 Scheduled Task Fixed ✅
- `V14PaperBot` task had `StopOnIdleEnd=true` causing crash loop
- First two PS approaches failed:
  - `$task.Settings.IdleSettings.StopOnIdleEnd = $false` → PropertyNotFound (read-only object)
  - `New-ScheduledTaskSettingsSet` + `Set-ScheduledTask -Settings` → "missing required element" (needs action+trigger too)
- **Working approach:** Export XML → modify → re-register:
  ```powershell
  $xml = [xml](Export-ScheduledTask -TaskName "V14PaperBot")
  $xml.Task.Settings.IdleSettings.StopOnIdleEnd = "false"
  Register-ScheduledTask -TaskName "V14PaperBot" -Xml $xml.OuterXml -Force
  ```
- **Lesson:** PowerShell Scheduled Task objects from `Get-ScheduledTask` have read-only nested properties. XML export/modify/re-register is the reliable pattern.

## Key Lessons
1. **Broken git submodules silently kill GitHub Pages** — check `git submodule status`
2. **PowerShell Scheduled Task XML export/modify/re-register** — the only reliable way to change nested settings
3. **`history_days` ≠ backtest duration** — always use explicit start date
4. **Simple daily ROI > compound** for user-facing numbers — matches intuition
5. **HTML entities > raw emoji** for cross-platform rendering
6. **Scanner `short_pnl` was dollars displayed as %** — always verify what dashboard fields actually represent
