## Mass file-deletion incident + full recovery (major)

**Trigger:** Brett reported "windows script failures" ~07:37 PST. All 4 bots + scanner down, auto-restarts "failing."

**Root cause:** 442 git-tracked files (~75% of repo) were physically deleted from disk — including the `trading/spot/engine/` package, every bot runner, `exchange_client.py`, `projects/`, `memory/`, `scripts/`. Caused by a **machine reboot** (Brett rebooted to clear a separate blockage) reconciling the working tree to a **corrupt/divergent git index** (local `main` ahead 5, behind 4455 vs `origin/main`). Only git-*tracked* files vanished; untracked `.bak` copies survived — the classic git fingerprint.

**Ruled out (confirmed, not a breach):** Not malware (no Defender detections, Defender 5007 events were just post-reboot re-init), not user deletion, not the hardened dashboard sync (operates on a `%TEMP%` clone only), not OneDrive (workspace not under OneDrive path, no cloud placeholders). Brett confirmed he didn't delete anything and did reboot. Brett asked directly if it was a security breach — answered no, with evidence; he said skip breach checks, proceed with fix.

**Recovery steps:**
1. Restored all 442 files byte-exact from HEAD blobs via `git cat-file blob <hash> > path` (cmd redirection). NOTE: PowerShell `Set-Content -NoNewline` / `WriteAllBytes` mangled encoding+newlines — do NOT use for binary-exact restore. Verified each with `git hash-object` == HEAD blob.
2. Divergence: confirmed all 4455 remote-only commits were 100% automated "Data sync" (zero code). Insurance first: `git tag verified-good-20261105-0750` + `git bundle create` (67.7MB, on Desktop). Then `git push --force-with-lease` → remote matches local code history (ahead 0 / behind 0).
3. Bots relaunched via their real scheduled task names (`V14PMLiveAster`, `V14PMPaperBot`, `V14PaperBot`, `V14ETFPaperBot`). Live bot PID-verified, TPs (AAVE/ZRO/NEAR) open, layer recon clean.

## Git push lesson (this repo)
- GeeGee's `AIT_DashboardSync` (10-min) races manual pushes. Hand-stash+rebase got tangled (paused rebase, detached HEAD, file briefly off-disk — recovered via `git rebase --abort`, commit object survived). **Correct pattern: `git -c rebase.autoStash=true rebase origin/main` then `git push`.** Never force-push once remote is clean (only data-sync commits behind).
